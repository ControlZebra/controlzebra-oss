# Security Policy

## Report a vulnerability privately

Use GitHub's [private vulnerability reporting form](https://github.com/ControlZebra/controlzebra-oss/security/advisories/new) to report suspected security issues in ControlZebra. You can also open the repository's **Security** tab and select **Report a vulnerability**.

If you cannot use GitHub's reporting form, email [support.controlzebra@gmail.com](mailto:support.controlzebra@gmail.com).

Do not disclose vulnerabilities in public issues, discussions, or change requests.

Include:

- The ControlZebra version or source revision and operating system.
- A description of the issue and its potential impact.
- Steps to reproduce it, with a minimal example if possible.
- Any suggested fix or workaround.

Use a test project. Do not include passwords, access tokens, customer projects, or confidential PLC/HMI files. Only test systems and data you own or are authorized to test.

## Follow-up and disclosure

Keep follow-up details in the private report so maintainers can assess affected versions, discuss a fix, and coordinate public disclosure with you. Report suspected vulnerabilities even if you are unsure whether your version is affected.

For ordinary bugs and feature requests, use [GitHub Issues](https://github.com/ControlZebra/controlzebra-oss/issues).
